# Contributing

## Before you start

- Read the README and existing issues.
- Keep each change focused on one problem.
- Do not commit secrets, private data, generated build output, or local configuration.

## Pull requests

1. Explain the problem and the intended behavior.
2. Keep unrelated formatting changes out of the diff.
3. Run the project's available tests, lint, or build checks.
4. Include verification details in the pull request description.

## Issues

Use an issue for reproducible bugs, concrete improvements, or missing documentation. Include the expected behavior and enough context to reproduce the problem.
